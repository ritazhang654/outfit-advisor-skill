# 从零搭建与部署

按顺序做，约 10 分钟能跑起来。

## 0. 前置条件

- 一个扣子账号（[coze.cn](https://www.coze.cn)），个人版即可
- 项目副本：通过项目分享链接「复制项目」，或从代码仓库导入

## 1. 复制项目

复制到**自己的工作空间**。复制带走的是代码与项目配置，**不会带走原作者的数据库数据**；三项内置集成会在你的空间里生成全新的独立资源。

## 2. 开通三项内置集成

在扣子编程项目里确认已添加（开发过程中 Agent 通常会自动引导；若接口报集成不可用，手动添加一次）：

1. **数据库**（Supabase / Postgres）
2. **对象存储**（S3）
3. **大语言模型**（LLM，需多模态）

凭据由平台运行时自动注入（如 `COZE_SUPABASE_URL`），**不需要**手动往 `.env` 里填任何 Key。

## 3. 初始化数据库

在数据库 / SQL 控制台，整段执行 `assets/init-db.sql`。成功后应有 **9 张表**。脚本全部 `IF NOT EXISTS`，可重复执行，不会清空已有数据。

> 如果只执行了旧版脚本（7 张表），缺 `ootd_records` 和 `foods`，OOTD 与食品库页面会报错。补执行最新脚本即可。

## 4. 本地预览验证

逐项验证，缺哪项回去补对应集成：

- 首页能打开；设置里填城市（如「杭州」）后能出天气
- 衣橱上传一张衣服图 → 能识别出品类与名称
- 美妆柜新增一条 → 成功
- 食品库点「添加食品」→ 顶部「拍照识别」上传一张包装图 → 能自动填出名称 / 类别 / 有效期
- 订阅新增一条 → 月均费用能算出来

## 5. 部署上线

点右上角**部署 → 开始部署**，默认配置即可，约 1–3 分钟得到 `https://<前缀>.coze.site`。

部署时环境变量与集成随项目走，无需额外配置。可按需加自定义域名、调整可见性。

## 6. （可选）分享给别人

项目页右上角**分享图标**：

- **分享产物**：给生产 URL，对方直接用你的线上应用
- **分享完整项目**：设为公开可见、允许复制、可设永久有效期；对方复制后得到独立代码与独立数据库，需自行执行一次建库脚本

## 常见问题

**Q：页面报「Supabase project configuration is unavailable」**
A：第 2 步的数据库集成未开通。添加后重新运行。

**Q：上传图片失败**
A：检查对象存储集成是否开通；默认区域 `cn-beijing`（见 `src/lib/storage.ts`）。

**Q：天气一直失败**
A：确认城市名能被 Open-Meteo 识别（用国内常见城市名）。天气失败不会阻断穿搭推荐，只是不带天气信息。

**Q：AI 识别 / 推荐报错**
A：确认 LLM 多模态集成可用。各接口都有降级：识别失败可手工填，文案失败不阻塞主流程。

**Q：食品拍照识别出来的类别不准**
A：模型返回的是自然语言，代码里做了白名单 + 别名映射（`normalizeFoodCategory`）。要扩类别，同时改 `src/lib/types.ts` 的枚举、`src/lib/llm.ts` 的提示词白名单与别名表。

**Q：会复制到原作者的数据吗**
A：不会。复制只带走代码，数据库是你空间里的新库，需执行一次建表脚本。
